Introdução e Objetivos do Projeto

Contextualização

A modernização de clínicas médicas de pequeno e médio porte exige a integração entre metodologias ágeis de planejamento, regras de negócio matematicamente consistentes, estruturas de dados eficientes e modelagem de requisitos precisa.

O sistema Clínica Vida+ consolida cinco pilares fundamentais da engenharia de software em um portfólio funcional, utilizando exclusivamente dados fictícios para fins didáticos e demonstrativos.

MODALIDADE 1: CONSULTA NORMAL

          
(A ∧ B ∧ C) ∨ (B ∧ C ∧ D)

          

            Libera atendimento quando há médico disponível e documentos válidos, somados ao agendamento prévio ou pagamentos em dia.
          

          

            Situações liberadas (V): 3 de 16 combinações (18,75%)
          

        


        

          
MODALIDADE 2: EMERGÊNCIA

          
C ∧ (B ∨ D)

          

            Libera atendimento imediato sempre que houver médico disponível e pelo menos documentação válida ou pagamentos em dia.
          

          

            Situações liberadas (V): 6 de 16 combinações (37,50%)
          

        

      


      
      

        

          🔎 Estudo de Caso Específico: A = F, B = V, C = V, D = F (Linha 12 das Tabelas)
        

        

          Cenário prático: O paciente chega à clínica sem agendamento prévio (A = F) e com pendência financeira (D = F), porém apresenta documentos válidos (B = V) e há médico disponível (C = V).
        

        

          

            1. Consulta Normal: (A ∧ B ∧ C) ∨ (B ∧ C ∧ D)

            
              Substituindo: (F ∧ V ∧ V) ∨ (V ∧ V ∧ F) = F ∨ F = F (Bloqueado)

              Explicação: Embora haja médico e documentos válidos, ambas as cláusulas falham porque falta agendamento (A=F) na primeira e falta pagamento em dia (D=F) na segunda.
            
          

          

            2. Emergência: C ∧ (B ∨ D)

            
              Substituindo: V ∧ (V ∨ F) = V ∧ V = V (Liberado)

              Explicação: Como há médico disponível (C=V) e a disjunção (B ∨ D) é verdadeira devido aos documentos válidos (B=V), o atendimento de emergência é imediatamente autorizado.

          Passo 4 • Estruturas de Dados Lineares
          
Algoritmo de Atendimento em Fila FIFO (First-In, First-Out)

        

      


      

        

          

            

              📄 pseudocodigo_fila_fifo.alg (Portugol Estruturado)
              FIFO • Ordem de Chegada
            

            
ALGORITMO Gestao_Fila_Atendimento_FIFO
// Definição do registro de cada paciente
TIPO Paciente = REGISTRO
    nome: CARACTERE
    cpf: CARACTERE
FIM_REGISTRO

VAR
    fila: VETOR[1..10] DE Paciente
    inicio, fim, i: INTEIRO
    atendido: Paciente

INICIO
    // Inicialização da fila vazia
    inicio <- 1
    fim <- 0

    // 1. Inserção (Enqueue) de 3 pacientes na ordem de chegada
    fim <- fim + 1
    fila[fim].nome <- "Mariana Silva"
    fila[fim].cpf  <- "111.222.333-44"

    fim <- fim + 1
    fila[fim].nome <- "Carlos Eduardo Souza"
    fila[fim].cpf  <- "555.666.777-88"

    fim <- fim + 1
    fila[fim].nome <- "Fernanda Oliveira"
    fila[fim].cpf  <- "999.888.777-66"

    ESCREVAL("=== FILA INICIAL (3 PACIENTES) ===")
    PARA i DE inicio ATE fim FACA
        ESCREVAL(i, "º - Nome: ", fila[i].nome, " | CPF: ", fila[i].cpf)
    FIM_PARA

    // 2. Remoção (Dequeue) do primeiro paciente para atendimento
    SE (inicio <= fim) ENTAO
        atendido <- fila[inicio]
        inicio <- inicio + 1
        ESCREVAL("")
        ESCREVAL(">> EM ATENDIMENTO AGORA: ", atendido.nome, " (CPF: ", atendido.cpf, ")")
    FIM_SE

    // 3. Exibição dos 2 pacientes restantes na ordem correta
    ESCREVAL("")
    ESCREVAL("=== PACIENTES RESTANTES NA FILA (ORDEM FIFO) ===")
    PARA i DE inicio ATE fim FACA
        ESCREVAL((i - inicio + 1), "º da fila - Nome: ", fila[i].nome, " | CPF: ", fila[i].cpf)
    FIM_PARA
FIM

          

        


        

          

            
Explicação Técnica do Funcionamento FIFO

            

              Uma fila FIFO (First-In, First-Out) garante que o primeiro elemento inserido seja obrigatoriamente o primeiro a ser removido, preservando a justiça da ordem de chegada na recepção da clínica.
            

            
    
              
  • Enfileirar (Enqueue): O ponteiro fim avança de 0 até 3 conforme Mariana, Carlos e Fernanda chegam.
    • 
              
  • Desenfileirar (Dequeue): O paciente apontado por inicio (Mariana Silva, posição 1) é chamado e inicio é incrementado para 2.
    • 
              
  • Preservação da Ordem: Ao percorrer de inicio (2) até fim (3), os dois pacientes restantes são exibidos exatamente na sequência em que entraram: 1º Carlos Eduardo Souza e 2º Fernanda Oliveira.
    •
